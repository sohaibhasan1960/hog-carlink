# HOG CarLink

HOG CarLink is a modified version of [Headswap](https://github.com/YegorkaPomidorka/headswap) 2.6.0
by Egor (YegorkaPomidorka), licensed under GPL-3.0 (see `LICENSE`; `pc-headunit/proto/*.proto` are AGPL-3.0).
Modified by Sohaib Alomari, 2026-10-30, for one car: VW ID.6 CROZZ (CarLife head unit "VW BT 5075", channel 20082128).

Changes against upstream tag `v2.6.0` (see `git log v2.6.0..`):

- package `com.hog.carlink`, name "HOG CarLink", own signing key; self-update from upstream disabled
- auto-start: CompanionDeviceManager presence service wakes the app when the car connects over Bluetooth (next to the ACL receiver)
- default video 800x480 (the head unit's native size)
- VW BT 5075 treated like VW BT 1420 over Wi-Fi: heartbeat on PAUSE, fast resume
- Arabic text for the head unit server warnings
- 2.6.0-hog.2: re-request the car Wi-Fi network (up to 10 times, 5 s apart) after onUnavailable; an approved request on Android 16 gives up after 3 scans
- 2.6.0-hog.3: restart the car network request when the car appears over Bluetooth or Wait is pressed again; "HOG CarLink" on the start screen
- 2.6.0-hog.4: HOG logo (icon, notification, head unit start screen), HOG CarLink name in all UI and log/report files, Arabic translation, wireless onboarding (car Wi-Fi and car pick steps)
- 2.6.0-hog.5: self-update from github.com/sohaibhasan1960/hog-carlink releases (asset hog-carlink-<version>.apk)
- 2.6.0-hog.6: HOG colors; home screen waits for the car instead of a cable when the car and its Wi-Fi are set
- 2.6.0-hog.7: map video on the ID.6 - 30 fps by default (one-time switch from saved 15), Android Auto UI density 140 at 800x480
- 2.6.0-hog.8: VideoMode ID6 (AA 1280x720 with 32 px vertical margins -> 1280x688 area, squeezed to 800x480 so the ID.6 window shows it at 1.86:1) and ID6_HD (same area sent as 1280x688; CarLifeSession probes it and falls back to ID6 if the head unit sends no START in 8 s, repeats INIT or closes the socket, remembering the fallback in prefs); AA per-frame log lines sampled (20 first, then every 300th) so reports cover whole trips; head-unit banner texts localized (strings_banner.xml); one-time prefs migration R800 -> ID6_HD; note: CarSettings() and therefore every CarPreset without an explicit mode now default to ID6_HD
- 2.6.0-hog.9: phone calls (AudioManager mode IN_CALL/IN_COMMUNICATION, polled once a second via ThermalSource.inCall) throttle transcoding like ThermalLevel.HOT (15 fps, half bitrate) and are logged (`звонок:` lines, WL `call state=`); encoder asks KEY_LATENCY=1, and where FEATURE_IntraRefresh is supported uses a 4 s GOP with intra refresh instead of an IDR every second (tuning "nolat"/"nointra" restore the old behaviour)
- 2.6.0-hog.10: decoder frame loss asks AA for a keyframe on the next tick instead of after KEYFRAME_WAIT_MS (each loss froze the head unit 1.5-2.6 s; five in 25 s made it close the link); two losses within 60 s mark the phone overloaded and hold ThermalLevel.WARM (20 fps, 0.75 bitrate) until a minute passes without losses (`нагрузка:` lines, WL `overload state=`); ID6_HD bitrate 5 -> 4 Mbit/s; BridgeHost.GRACE_MS 8 -> 30 s so the ID.6, which reconnects 5-15 s after its own EOF, resumes without the "connecting Android Auto" banner
- 2.6.0-hog.11: "Find nearby networks" button in the car Wi-Fi form (settings and onboarding): link/car/WifiScan lists Wi-Fi networks in range by signal and fills the SSID; needs ACCESS_FINE_LOCATION (manifest maxSdkVersion removed) and Location on; the password stays manual because saved networks are hidden from apps
- 2.6.0-hog.12: ID6 / ID6_HD Android Auto density 224 -> 240 (larger icons and text on the ID.6 screen, ~853 dp wide)
- 2.6.0-hog.13: head-unit banner redesigned (dark HOG panel + title and step lines, RTL-aware; strings_banner.xml lines split by \n); VoIP counts as a call only while some app records the mic (WhatsApp voice notes no longer throttle video); hot phone at connect (thermal >= MODERATE) starts the session in ID6 800x480 instead of ID6_HD; ID6 density 240 -> 232; Share button on home (latest GitHub release link); server-stopped notification says what to tap
- 2.6.0-hog.14: car recognition - defaults back to generic (R720, 15 fps) for any CarLife car; when the head unit reports STATISTIC_INFO channel 20082128 (VW ID.6 CROZZ) AaPrefs.learnCar writes ID6_HD + 30 fps once (unless the user chose otherwise), applied from the next AA connection; older installs get those values written explicitly (hogTune3) so nothing changes for them
- 2.6.0-hog.15: in-app support over Firebase (project hog-carlink) without SDKs - support/SupportCloud (Identity Toolkit anonymous sign-in + Firestore REST via HttpURLConnection), ui/SupportScreen (customer request form + my requests; owner inbox with reply/report/delete after entering the owner code, long-press on the version line), support/SupportJob (JobScheduler ~30 min: new requests for the owner, replies for customers). Access is enforced by Firestore rules kept in the Firebase console (owner code lives there, not in this repo)
- 2.6.0-hog.16: hotfix - ACCESS_NETWORK_STATE permission (JobScheduler network constraint threw SecurityException on Android 14+, crashing the app right after the owner code and then on every launch); SupportJob.schedule never throws
- 2.6.0-hog.17: phase 1 from the upstream/protocol review - START_STICKY restart after the system kills the process mid-session (upstream 6dbf659, h610: resumes when the chosen car is near over Bluetooth); REQUEST_GO_TO_FOREGROUND (0x00010038) sent once when the head unit gives no VIDEO_ENCODER_START after INIT_DONE; GEAR_INFO id fixed 0x00010029 -> 0x00018029 (Baidu MSG_CMD_CAR_GEAR); IDR-size insurance (IDR > 450 KB -> bitrate ceiling x0.75) also for channel 20082128 (VW ID.6), without the 2 Mbit/s start cap that upstream uses for a USB EIO case
- 4.0.0-hog.18: phase 2 - merged upstream main (4.0.0-beta6, 201 commits: passthrough 3.0 with SPS crop and own IDR, FPS Auto, call state to the head unit, HU_GEAR_INFO, Headswap Desktop launcher mode, onboarding mode step). AaPrefs.migrateTo30 switches existing installs to passthrough; ID6_HD (1280x688) is SPS-croppable so the ID.6 runs without transcoding, while ID6 (800x480 fallback) stays itself in passthrough and forces transcoding (VideoMode.effective). Hot-at-connect ID6_HD -> ID6 switch only when transcoding. HOG's IDR guard for 20082128 kept next to upstream's VW_ID_IDR_LIMIT_HUS ("VW BT 9491" only). Upstream's HU_GEAR_INFO (0x00018029) supersedes the hog.17 gear-id change: GEAR_INFO is back to 0x00010029. R1440 dropped (upstream removed it). REQ_WIFI_SCAN 40 -> 43 (upstream took 40-42). Updater stays on with HOG releases. Arabic added for the new settings/onboarding/home/upgrade texts; the launcher, desktop and developer screens stay in English
- 4.0.0-hog.19: head unit apps - AABrowser and Fermata install from their official GitHub releases inside the app (apps/CarAppInstaller): latest release via API, APK by name pattern, size + SHA-256 against the release digest, package name and author signing certificate pinned in apps/CarApp, then PackageInstaller; shown in the existing "Head unit apps" settings section (Install / Update with progress) and linked from home. Build: `cd android && ./gradlew assembleRelease`. Needs JDK 17+, Android SDK platform 37,
`~/.android-keys/carlink-release.properties`, and the AA head unit certs in
`android/app/src/main/assets/aa/{hur,jvc}/` (not in git; taken from the official Headswap 2.6.0 APK).
